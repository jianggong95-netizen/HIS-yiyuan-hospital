# 常见问题

## 关于仓库

### Q1：这个仓库是开源项目吗？

**代码是开源的**，采用 [Apache License 2.0](../LICENSE)：可以自由使用、修改、分发，也可以商用，只需保留 `LICENSE` 与 `NOTICE` 中的版权声明。

但它同时是坐标软件集团的**产品演示与能力展示仓库**：`packages/`、`mock-server/`、`examples/` 是示例 / 占位实现，用于让医院信息科、集成商、合作伙伴快速了解 HIS-yiyuan-hospital 的能力边界与接口形态。

需要区分两件事：

- **本仓库的代码** → Apache-2.0，免费用；
- **完整产品（生产版本、实施、运维、等保与测评支撑）** → 商业授权，通过官网商务渠道获取。

产品名称、商标与界面截图的授权范围见 [README](../README.md) 的「许可与版权」一节，法律条款以 [LICENSE](../LICENSE) 为准。

### Q2：为什么代码里只有几个模块？

演示仓库聚焦"一条主链路"：患者 360 → 合理用药校验 → 预约取号。目的是让人 10 分钟看懂接口风格与数据模型，而不是复刻 120+ 微服务。完整模块清单见 [modules.md](./modules.md)。

### Q3：数据是真的吗？

全部虚构。"李依依""MZ00000143""0101019900307258" 均为测试数据，与任何真实患者无关。仓库内不含任何院内数据、患者信息或生产配置。

### Q4：可以提 PR 吗？

欢迎提 Issue 反馈文档错误、接口设计建议、演示数据补充。代码类 PR 请先开 Issue 讨论，因为演示仓库与生产代码库是分离的。

## 关于产品

### Q5：和传统 HIS 厂商的关系是替代还是共存？

共存优先。HIS-yiyuan-hospital 通过集成平台与院内既有系统对接（HL7 / WebService / REST / 数据库视图），可以先上中台与 CDR，再逐步替换业务模块。绝大多数客户是**分批上线**，不做一次性整体切换。

### Q6：能支撑多院区 / 医共体吗？

可以。支持多法人、多院区、多套价格体系与集团级标准字典，医共体场景下支持成员单位数据分级汇聚、检查检验互认、双向转诊。

### Q7：电子病历分级评价和互联互通测评能支撑吗？

可以。EMR 提供结构化病历、环节质控、闭环数据；集成平台提供互联互通测评所需的共享文档库、交互服务与测评材料支撑。具体目标等级需结合医院现状评估，实施团队会出具差距分析报告。

### Q8：支持信创吗？

支持。已完成鲲鹏 / 飞腾 / 海光 + 麒麟 / 统信 + 达梦 / 金仓的全栈适配，详见 [deployment.md](./deployment.md)。

### Q9：上云还是本地部署？

两种都支持，多数三级医院选择私有化部署（数据不出院），互联网医院与患者服务类业务可放在专有云。

### Q10：实施周期多久？

取决于上线范围与接口数量。单院区核心业务通常按"分批上线"推进，中台 + 集成平台先行，业务模块按科室分批切换。具体排期在调研后出具实施方案。

## 关于演示环境

### Q11：`node mock-server/index.js` 起不来？

```bash
node -v            # 需要 ≥ 18
lsof -i :8787      # macOS/Linux 查端口占用
netstat -ano | findstr 8787   # Windows
```

端口被占用就换端口：`PORT=8899 node mock-server/index.js`。

### Q12：示例页打开是空白 / 提示接口未就绪？

必须通过 `http://localhost:8787/` 访问（由 Mock 网关托管），直接双击 `index.html` 会因为跨域与相对路径失败。

### Q13：想换成自己医院的接口？

改 `examples/patient-360/index.html` 里的 `API` 常量，或直接用 SDK 指定 `baseUrl`。数据模型见 [api/README.md](./api/README.md)。

### Q14：能提供 Postman / Apifox 集合吗？

可以。演示接口集合可基于 [api/README.md](./api/README.md) 的清单快速生成；生产接口集合属于交付资料，随项目提供。
